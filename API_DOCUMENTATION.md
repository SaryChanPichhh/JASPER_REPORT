## 1. Architecture & Protocol Overview

The Report Service produces compiled documents generated by **JasperReports 7.0.8** using Clean Architecture.

- **Request Format:** All endpoints are `POST` requests consuming `Content-Type: application/json`.
- **Response Format:** Binary stream `ResponseEntity<byte[]>` containing the generated document.
- **Content-Disposition:** Always includes an attachment header specifying the download filename:  
  `Content-Disposition: attachment; filename="<ReportName>.<extension>"`
- **Response MIME Types:**
  - `PDF`: `application/pdf`
  - `XLSX`: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
  - `DOCX`: `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
  - `CSV`: `text/csv`
- **Khmer Unicode Support:** Fully embedded with `Khmer OS`, `Khmer OS Muol`, `Khmer OS Battambang`, and `Khmer OS Siemreap` fonts via PDF `Identity-H` encoding. No square glyphs or broken text.

## 3. Common Request Parameters

All DTOs inherit from `GenerateReportCommand`. You can include these fields in any request payload:

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `format` | `String` | No | `"PDF"` | Output format: `"PDF"`, `"XLSX"`, `"DOCX"`, or `"CSV"`. Case-insensitive. |
| `reportName` | `String` | Optional* | *Auto-selected* | Target Jasper template. Controls variations such as A4 vs 80mm receipt. |
| `currencySymbol` | `String` | No | `"$"` | Main currency prefix symbol (e.g., `"$"`, `"€"`, `"£"`). |
| `subCurrencySymbol` | `String` | No | `"KHR"` | Secondary currency symbol for dual-currency calculations (e.g. `"KHR"`). |
| `Language` | `String` | No | `"ENG"` | Language enum: `"ENG"` (2), `"KM"` (1), `"ZH_CH"` (3), `"ZH_TW"` (4). |
| `DecimalPrecision` | `String` | No | `"TwoDecimalWithTrailingZero"` | Number formatting option (see Decimal Table below). |
| `SubDecimalPrecision` | `String` | No | `"Standard"` | Precision formatting for secondary currency. |
| `dbCode` | `String` | No | `null` | Multi-tenant or database routing code (if applicable). |

### Decimal Precision Options
- `"Standard"`: `{0:#,###,##0}` (no decimals, rounded integer)
- `"TwoDecimalPrecision"`: `{0:# ### ##0.##}` (up to 2 decimals)
- `"TwoDecimalWithTrailingZero"`: `{0:# ### ##0.00}` (strictly 2 decimal places, e.g. `12.50`)
- `"ThreeDecimalWithTrailingZero"`: `{0:# ### ##0.000}`
- `"FourDecimalWithTrailingZero"`: `{0:# ### ##0.0000}`

## 5. Frontend Developer Integration Guide

### Handling Binary Streams (Blob)

Because the endpoints return **raw binary bytes** (`application/pdf`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, etc.), you **MUST** configure your HTTP client to receive the response as a `blob`.

> [!WARNING]
> If you omit `responseType: 'blob'`, your browser will parse the binary file as a text string, corrupting the PDF or Excel document.

---

### Action 1: Direct File Download

```typescript
import axios from 'axios';

export async function downloadReport(endpoint: string, payload: any, defaultFilename = 'report.pdf') {
  const response = await axios.post(`http://localhost:8080/api/v1/reports/${endpoint}`, payload, {
    responseType: 'blob', // Crucial!
    headers: {
      'Content-Type': 'application/json'
    }
  });

  // Extract filename from Content-Disposition header if available
  const disposition = response.headers['content-disposition'];
  let filename = defaultFilename;
  if (disposition && disposition.includes('filename=')) {
    const match = disposition.match(/filename="?([^";]+)"?/);
    if (match?.[1]) filename = match[1];
  }

  // Create temporary anchor to trigger browser download
  const blob = new Blob([response.data], { type: response.headers['content-type'] });
  const downloadUrl = window.URL.createObjectURL(blob);
  const link = document.createElement('a');
  link.href = downloadUrl;
  link.setAttribute('download', filename);
  document.body.appendChild(link);
  link.click();
  link.remove();
  window.URL.revokeObjectURL(downloadUrl);
}
```

## 7. Error Handling & Status Codes

The service enforces strict validation via `@Valid` and returns structured JSON responses on failure.

### Status Code Reference

| Status Code | Error Code | Cause |
|-------------|------------|-------|
| `200 OK` | — | Report compiled and exported successfully. Binary bytes returned. |
| `400 BAD REQUEST` | `VALIDATION_FAILED` | Missing or invalid required fields (e.g. blank `reportName`). |
| `400 BAD REQUEST` | `INVALID_ARGUMENT` | Invalid parameters provided in the command. |
| `404 NOT FOUND` | `TEMPLATE_NOT_FOUND` | Specified JRXML/Jasper template does not exist on disk or in DB. |
| `500 INTERNAL_SERVER_ERROR` | `REPORT_GENERATION_FAILED` | JasperReports compilation error, corrupt subreport, or unhandled exception. |

### Error Response Schema Example (JSON)
When a validation or runtime error occurs, the server responds with:

```json
{
  "timestamp": "2026-10-02T15:40:12.345678",
  "status": 400,
  "error": "VALIDATION_FAILED",
  "details": {
    "reportName": "Report name must not be blank"
  }
}
```

Or for a missing template:

```json
{
  "timestamp": "2026-10-02T15:42:01.123456",
  "status": 404,
  "error": "TEMPLATE_NOT_FOUND",
  "message": "Report template 'NonExistentTemplate' not found. Looked in DB and classpath locations."
}
```
